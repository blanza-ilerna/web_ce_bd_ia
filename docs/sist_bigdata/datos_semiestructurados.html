1.3.3.2 Extracción de Datos Semi-estructurados

Más allá de las tablas: procesando jerarquías y esquemas flexibles

Los datos semi-estructurados representan un puente entre el rigor del SQL y el caos del texto libre. Aunque no residen en tablas fijas, contienen etiquetas y jerarquías (como JSON, XML o YAML) que permiten su interpretación programática. En Big Data, estos formatos son el estándar para el intercambio de información entre microservicios, APIs y bases de datos NoSQL.

La clave de su éxito radica en la flexibilidad: permiten evolucionar el modelo de datos sin romper los sistemas que consumen la información.

El Triunvirato de los Formatos

📦

JSON: El Estándar Moderno

Ligero, legible y nativo de la web. Es el formato preferido para **APIs REST** y bases de datos de documentos. Su esquema variable permite anidar estructuras complejas de forma intuitiva.

📜

XML: Rigor y Jerarquía

Más verboso pero altamente estricto. Prevalente en entornos corporativos legados, sistemas financieros (ISO 20022) y protocolos SOAP. Utiliza etiquetas personalizadas y esquemas de validación (XSD).

⚙️

YAML: Configuración Humana

Orientado a la legibilidad extrema. Es el lenguaje por excelencia para archivos de configuración en herramientas de orquestación como **Kubernetes**, **Docker Compose** o Ansible.

Estrategias de Extracción y Parsing

🔍 Procesamiento en Memoria (DOM)

Carga el documento completo como un árbol navegable. Es ideal para archivos pequeños o medianos donde necesitamos realizar múltiples saltos entre etiquetas o nodos.

⚡ Procesamiento Streaming (SAX / ijson)

Lee el archivo de forma secuencial mediante eventos. Consume una memoria constante, lo que lo hace indispensable para procesar archivos JSON o XML de varios gigabytes.

Extracción desde API REST (Python)

api_extractor.py 
import requests

def extraer_datos_paginados(url_base, num_paginas):
    dataset_final = []
    
    for pagina in range(1, num_paginas + 1):
        params = {'page': pagina, 'status': 'active'}
        response = requests.get(url_base, params=params)
        
        if response.status_code == 200:
            # La respuesta JSON se convierte automáticamente en dict/list de Python
            datos_json = response.json()
            dataset_final.extend(datos_json['resultados'])
        else:
            print(f"Error en página {pagina}: {response.status_code}")
            
    return dataset_final

El Desafío del Esquema Variable

🛠️

Validación y Robustez

A diferencia de SQL, en semi-estructurados un campo puede ser opcional o cambiar de tipo entre documentos. La extracción profesional debe incluir **validaciones de presencia** y manejo de valores por defecto para evitar errores en cascada. En bases de datos NoSQL como **MongoDB**, aprovechamos las proyecciones y filtros del motor para extraer solo los fragmentos necesarios, minimizando el tráfico de red.
