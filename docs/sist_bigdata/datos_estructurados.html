1.3.3.1 Extracción de Datos Estructurados

Change Data Capture (CDC): Sincronización incremental de alta precisión

En el análisis de datos masivos, extraer repetidamente tablas relacionales completas es una estrategia insostenible. El Change Data Capture (CDC) es una técnica avanzada que captura únicamente las variaciones (inserciones, actualizaciones y eliminaciones) realizadas en la base de datos origen. Esto permite mantener sincronizado el sistema de análisis con el operativo de forma casi instantánea y con un impacto mínimo.

El CDC transforma la extracción de una "foto fija" pesada en un "flujo continuo" de cambios, optimizando drásticamente el uso de red y almacenamiento.

Metodologías de Captura de Cambios

🕒

Enfoque basado en Timestamps

Utiliza columnas como `last_updated` para filtrar registros. Es el más fácil de implementar, pero requiere modificar el esquema de la tabla y tiene dificultades para detectar eliminaciones físicas (*hard deletes*).

📜

Enfoque basado en Logs (Binlog/WAL)

Lee directamente los registros de transacciones del motor de la base de datos. Es el método más preciso y eficiente, ya que captura eliminaciones y no requiere alterar las tablas originales.

⚡

Enfoque basado en Triggers

Disparadores que graban cada cambio en una tabla de auditoría. Ofrece un control absoluto sobre el proceso de captura, pero introduce una penalización de rendimiento en cada operación de escritura (*overhead*).

Implementación Lógica de CDC (Timestamp)

incremental_extraction.sql 
-- 1. Definimos la marca de agua de la última extracción exitosa
SET @ultima_fecha = '2024-05-01 10:00:00';

-- 2. Consultamos solo los cambios ocurridos después de ese instante
SELECT 
    id_cliente, nombre, email, fecha_modificacion
FROM 
    clientes
WHERE 
    fecha_modificacion > @ultima_fecha
ORDER BY 
    fecha_modificacion ASC;

-- 3. Tras el éxito, actualizamos la 'ultima_fecha' en nuestro sistema de control

Comparativa de Métodos CDC

Criterio Basado en Logs Basado en Timestamps
Impacto en Origen Mínimo (Lectura asíncrona) Moderado (Queries SQL)
Detección de Deletes Soportado nativamente No soportado (requiere soft-delete)
Dificultad Implementación Alta (Requiere acceso a logs) Baja (SQL estándar)
Precisión Temporal Absoluta (Orden de log) Depende del reloj del servidor
