1.5.3.3 Spark Streaming

La potencia del ecosistema unificado: procesamiento de tiempo real mediante micro-batches

Spark Streaming es la extensión de Apache Spark diseñada para el procesamiento de datos en tiempo real. A diferencia del "True Streaming" de Flink, Spark utiliza un enfoque de Micro-batching: agrupa los eventos entrantes en pequeñas ventanas temporales (típicamente de 1 a 5 segundos) y los procesa como lotes ultra-rápidos utilizando el motor central de Spark.

Su mayor fortaleza no es la latencia mínima, sino la unificación: permite usar el mismo código, bibliotecas y APIs tanto para procesos históricos (Batch) como para flujos en vivo.

Criterio de Decisión Técnica

Apache Flink

Elegir cuando la latencia debe ser de **milisegundos** y la precisión evento-a-evento es innegociable (Detección de fraude, trading).

Spark Streaming

Elegir cuando una latencia de **segundos** es aceptable y se busca integración con SQL, ML o Grafos en un solo ecosistema.

Ventajas del Micro-batching

♻️

Reutilización de Código y Conocimiento

Los desarrolladores que ya conocen Spark pueden aplicar sus habilidades al streaming sin curva de aprendizaje. Las mismas funciones de transformación funcionan en ambos mundos.

🔗

Integración con MLlib y Spark SQL

Permite aplicar modelos de Machine Learning entrenados en batch directamente sobre el stream de datos, o realizar consultas SQL complejas sobre el flujo en vivo.

Evolución de las APIs

DStreams (Discretized Streams)

La API original. Representa el flujo como una secuencia de RDDs (resilient distributed datasets). Ofrece control total pero es más compleja de programar.

Structured Streaming

La API moderna. Trata el stream como una **tabla infinita** que crece continuamente. Permite usar exactamente el mismo código SQL para batch y streaming.

Resiliencia Basada en Linaje

🛠️

Recuperación Inteligente

Spark garantiza la tolerancia a fallos mediante el **linaje de RDDs**. Si un nodo falla, el sistema conoce exactamente qué pasos se siguieron para generar ese micro-batch y puede reconstruirlo desde la fuente original. Esto evita la necesidad de replicar datos costosos en memoria, optimizando los recursos del clúster.
