1.3.1 Introducción a la Extracción de Datos

El primer paso del pipeline: capturando valor desde fuentes heterogéneas

La extracción de información es la fase crítica donde comienza el ciclo de vida del dato. Consiste en recuperar información relevante desde fuentes diversas —desde bases de datos tradicionales hasta sensores en tiempo real— para transformarla en un formato estructurado y accionable. La eficiencia de esta etapa dicta la calidad de todo el análisis posterior.

No se trata solo de mover datos, sino de entender la semántica de cada fuente para garantizar la integridad y el valor de la información extraída.

Tipología de Fuentes de Datos

🗄️

Bases de Datos (SQL & NoSQL)

Desde sistemas relacionales (MySQL, PostgreSQL) hasta soluciones NoSQL como MongoDB (documentos JSON flexibles) o Cassandra (alto rendimiento distribuido). Cada una exige estrategias de consulta específicas para evitar saturar el sistema origen.

📄

Archivos y Logs

Fuentes ubicuas en Big Data. Los archivos CSV son ideales para tablas planas, JSON/XML para jerarquías complejas y los Logs del sistema para auditar comportamientos mediante *parsing* especializado.

🌐

Web APIs: REST & GraphQL

Acceso programático a servicios externos. Mientras que REST usa endpoints estándar, GraphQL permite solicitar solo los campos necesarios, optimizando el tráfico. Requieren gestionar autenticación y paginación.

📡

Streaming e IoT

Captura de eventos en tiempo real (redes sociales, sensores). A diferencia de la extracción batch, aquí se procesan flujos continuos con baja latencia mediante tecnologías como Apache Kafka o AWS Kinesis.

Desafíos de la Extracción

⚙️ Operativos

Manejo de conectividad, control de límites de velocidad (Rate Limits) y gestión de ventanas de tiempo para evitar impactos en el rendimiento de los sistemas transaccionales.

🏗️ Estructurales

Normalización de formatos heterogéneos, validación de esquemas dinámicos y limpieza inicial de datos corruptos o incompletos antes de entrar al Data Lake.

Calidad desde el Origen

Un proceso de extracción robusto es el seguro de vida de cualquier sistema de IA. Sin una captura fiable y limpia, los modelos predictivos posteriores perderán toda su utilidad ("Garbage In, Garbage Out").
