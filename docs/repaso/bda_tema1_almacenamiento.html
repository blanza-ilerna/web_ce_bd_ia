TIPOLOGÍAS DE ALMACENAMIENTO (DAS, NAS Y SAN) Y ALTA DISPONIBILIDAD

DAS (Direct Attached)

Almacenamiento directamente conectado al servidor (USB, SATA). Muy rápido y barato, pero no se puede compartir por red. Si el servidor cae, los datos quedan aislados.

NAS (Network Attached)

Almacenamiento compartido conectado a la red TCP/IP (como una "carpeta compartida" gigante). Opera a nivel de archivos (NFS, SMB/CIFS). Ideal para ofimática y archivos compartidos.

SAN (Storage Area Net.)

Red independiente de ultra-alta velocidad (Fibra Óptica/iSCSI) dedicada 100% al almacenamiento. Opera a nivel de bloques puros. Es el estándar para Bases de Datos masivas críticas y clústeres.

Alta Disponibilidad (HA) y Redundancia

La Alta Disponibilidad (HA) garantiza que los datos sigan accesibles incluso ante fallos críticos de hardware. Este estado se logra fundamentalmente mediante la redundancia (duplicidad de componentes y caminos de datos), evitando puntos únicos de fallo.

Configuraciones RAID (Redundancia y Rendimiento) Escalabilidad en Big Data
RAID 0 (Striping): Suma velocidad, 0% redundancia. Si falla 1 disco, pierdes todo.
RAID 1 (Mirroring): Espejo 1:1. Máxima seguridad pero doble coste de almacenamiento.
RAID 5 (Paridad simple): Requiere mín 3 discos. Tolera el fallo de 1 disco.
RAID 6 (Doble paridad): Requiere mín 4 discos. Tolera el fallo de 2 discos simultáneos.
RAID 01 vs 10: El RAID 10 (Divisiones de Espejos) es más robusto y rápido de reconstruir que el RAID 01 (Espejo de Divisiones). 		Scale-Up (Vertical): Añades más RAM a la misma placa base. Límite físico rápido.
Scale-Out (Horizontal): Añades millones de ordenadores baratos estándar interconectados. Es el pilar del Big Data para aumentar capacidad sin interrumpir operaciones.

ECOSISTEMA HADOOP, DATA LAKES Y CALIDAD DEL DATO

Calidad de los Datos

Se define por el grado en que los datos son precisos, completos y consistentes. Es el requisito indispensable para que el análisis sea fiable y aporte valor real al negocio.

Orquestación: Apache Oozie

Herramienta encargada de coordinar y gestionar los trabajos de Hadoop mediante flujos de trabajo (workflows) definidos en archivos XML.

Apache Hadoop (La Arquitectura Clásica)

  • HDFS: Divide archivos en bloques (128MB). El NameNode guarda el mapa de archivos en RAM; los DataNodes almacenan los bloques físicos replicados (x3).
  • MapReduce: Paradigma donde el cálculo viaja al dato. Map (filtra/trocea) y Reduce (resume/agrega).
  • YARN: El sistema operativo de Hadoop; gestiona y asigna recursos (CPU/RAM) a las aplicaciones.
  • Modelo WORM: Write Once, Read Many. Datos inmutables; una vez escritos en HDFS, no se pueden modificar, solo borrar o añadir.

Data Lakes, Spark y Delta Lake

  • Data Lake: Almacén de datos en crudo (sin esquema previo). Ideal para Big Data por su bajo coste y flexibilidad.
  • Apache Spark: Procesa en memoria (RAM), siendo hasta 100 veces más rápido que MapReduce. Usa RDDs (colecciones de objetos tolerantes a fallos).
  • Delta Lake: Añade **propiedades ACID** y versionado (Time Travel) al Data Lake, permitiendo actualizaciones seguras.

ANÁLISIS DE DATOS, INTELIGENCIA Y MONITORIZACIÓN

ETL, DWH e IA Aplicada

El proceso ETL permite transformar datos de múltiples fuentes antes de la carga central. El Data Warehouse almacena volúmenes de datos estructurados para análisis. La IA se aplica sobre estos datos para hacer predicciones o tomar decisiones basadas en patrones.

Análisis Descriptivo Análisis Predictivo Análisis Prescriptivo
¿Qué ha pasado?
Mirada al pasado usando BI tradicional. Ej: "Ventas de Abril cayeron 10%".		 ¿Qué pasará?
Aplicación de Machine Learning sobre históricos. Ej: "Caeremos 10% en Mayo".		 ¿Qué debo hacer?
IA avanzada que receta acciones. Ej: "Aplica descuento del 5% ahora para no caer".
Monitorización: Prometheus

Herramienta estándar para la recolección de métricas en tiempo real. Permite monitorizar la salud del clúster y el rendimiento de las aplicaciones masivas.

Tiempo Real (Spark vs Flink)

Spark Streaming: Micro-Batching (Lotes cada X ms). Fácil integración SQL.
Apache Flink: True Streaming (Evento a evento). Latencia submilisegundo (Uber/Netflix).

CLOUD Y MODELOS DE SERVICIO EN ALMACENAMIENTO

La adopción de tecnologías Cloud (AWS S3, Google Cloud Storage, Azure Blob) habilita el desacoplamiento de almacenamiento y computación, ofreciendo facturación nativa por gigabyte.

  • IaaS en Big Data: Te alquilan infraestructura (discos brutos). Tú instalas HDFS y gestionas todo.
  • PaaS en Big Data: Servicios gestionados (BigQuery, RDS). El Cloud asume la responsabilidad del hardware y auto-escala.
  • SaaS en Big Data: Analítica llave en mano (Power BI Cloud). El software está cerrado, tú solo usas los gráficos finales.
