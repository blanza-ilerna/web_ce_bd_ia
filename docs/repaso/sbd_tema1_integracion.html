ALGORITMIA, COMPLEJIDAD Y FUNDAMENTOS

MapReduce y Complejidad

Paradigma: Map (filtra/trocea) y Reduce (resume/junta).

Complejidad Big O: Mide eficiencia. O(1) es ideal; O(n²) es inviable para Big Data.

Amdahl, Grafos y Árboles

Ley de Amdahl: El código no-paralelizable limita la velocidad máxima.

Grafos: Relaciones (Nodos/Aristas) para Pagerank. B-Trees: Índices eficientes para DBs.

Fundamentos Matemáticos

M. Discreta: Estudia elementos contables (bits, registros). No existen "medios registros".

Latencia: Retraso de red; factor crítico junto al cómputo distribuido.

INTEGRACIÓN Y ARQUITECTURAS DE DATOS

ETL (Extract, Transform, Load) ELT (Extract, Load, Transform)
El servidor intermedio limpia los datos "al vuelo" antes de inyectarlos. Si hay error en la limpieza, el dato sucio original se pierde. Arquitectura clásica para poblar Data Warehouses. Carga los datos crudos rápido al pozo final (Load) y usa la fuerza del Cloud para procesarlos después (Transform). Estándar en Data Lakes; no hay riesgo de perder la historia original.
Arquitectura Lambda

Batch: Datos históricos (precisión).
Speed: Tiempo real (latencia).
Serving: Consulta unificada.

Arquitectura Kappa

Todo es Streaming. Elimina la capa Batch y trata la historia como un flujo continuo infinito (Apache Kafka).

Data Skew (Sesgo)

Fallo de rendimiento donde la carga se distribuye desigualmente; un nodo trabaja al 100% mientras otros esperan.

ECOSISTEMA DE ALMACENAMIENTO NoSQL

Teorema CAP (El Trilema)

Consistencia, Disponibilidad y Tolerancia a Particiones. Es matemáticamente imposible tener las 3. Si se corta la red, hay que elegir entre detener el sistema (CP) o dar datos desactualizados (AP).

ACID vs BASE (Propiedades)

ACID (SQL): Atomicidad, Consistencia, Isolation (Aislamiento), Durabilidad. Garantiza integridad total.

BASE (NoSQL): Basically Available (Básicamente disponible), Soft state (Estado blando), Eventual consistency (Consistencia eventual).

Redis (Clave-Valor)

Motor de altísimo rendimiento ideal para el almacenamiento de sesiones de usuario y cachés rápidas debido a su bajísima latencia.

Modelo NoSQL Ejemplos Clave Uso Ideal / Características
Documentales MongoDB / CouchDB JSON/BSON. Esquema flexible para apps web y catálogos.
Columnares Cassandra / HBase Escalabilidad masiva y consultas analíticas rápidas (OLAP).
Grafos Neo4j / Amazon Neptune Redes sociales, detección de fraude y caminos óptimos.
Clave-Valor Redis / Memcached Bajísima latencia. Sesiones de usuario y cachés en RAM.

CALIDAD Y GESTIÓN DEL DATO

Regla 1-10-100 (Coste del Error)

Mide el coste creciente de no corregir errores:

  • 1€: Al capturar el dato erróneo (Prevención).
  • 10€: Al tener que limpiarlo en la DB (Corrección).
  • 100€: Cuando el error impacta en el negocio (Fallo).
Dimensiones de la Calidad
  • Completitud: Grado de valores no nulos.
  • Exactitud: Fidelidad del dato con la realidad.
  • Consistencia: Datos iguales en distintos sistemas.
  • Validez: Cumplimiento de formatos y reglas.
  • Trazabilidad: Conocer el origen y cambios (Linaje).
