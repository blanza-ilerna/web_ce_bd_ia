2.2.4 Código: Configuración de Replicación en HDFS

Implementación y verificación de la durabilidad del dato en Hadoop

Para garantizar que un clúster HDFS sea tolerante a fallos, es necesario configurar correctamente el factor de replicación. A continuación, exploramos cómo establecer este parámetro de forma global en el sistema y cómo verificar programáticamente la integridad de los bloques utilizando Python y la biblioteca Snakebite.

Este flujo permite asegurar que la información crítica esté siempre triplicada, permitiendo al sistema recuperarse automáticamente ante la caída de cualquier nodo.

1. Configuración Global (HDFS)

hdfs-site.xml 
<configuration>
    <!-- Factor de replicación por defecto para cada bloque en el clúster -->
    <property>
        <name>dfs.replication</name>
        <value>3</value>
        <description>Asegura que cada bloque se guarde en 3 nodos distintos.</description>
    </property>
</configuration>

2. Verificación Programática (Python)

verify_hdfs_replication.py 
from snakebite.client import Client

# Configurar cliente HDFS conectando al NameNode
hdfs_client = Client("namenode_host", 8020, use_trash=False)

# Establecer factor de replicación específico para un archivo
file_path = "/data/sample_data.txt"
hdfs_client.set_replication(file_path, 3)

# Función para verificar el estado de los bloques tras un fallo
def check_replication_status(file_path):
    try:
        # Obtener metadatos del archivo
        file_info = hdfs_client.stat([file_path])[0]
        replication_factor = file_info['replication']
        print(f"Factor de replicación para {file_path}: {replication_factor}")

        # Escanear bloques para detectar corrupciones o ausencias
        for block in hdfs_client.ls([file_path], include_toplevel=True):
            if block['corrupt']:
                print(f"⚠️ Bloque corrupto detectado en {file_path}")
            else:
                print(f"✅ Bloques intactos para {file_path}")
                
    except Exception as e:
        print(f"Error crítico al verificar el estado: {e}")

# Ejecutar la auditoría de integridad
check_replication_status(file_path)

# Nota: En producción, se complementaría con comandos como `hdfs fsck /`
# para realizar una reparación profunda y rebalanceo del clúster.

Auditoría y Mantenimiento

Este ejemplo demuestra la dualidad de la gestión en Hadoop: la configuración declarativa mediante XML para el comportamiento por defecto y la manipulación imperativa mediante Python para auditorías dinámicas. La capacidad de verificar si un bloque está corrupto permite a los administradores de datos programar tareas de mantenimiento proactivas antes de que un fallo de hardware afecte la disponibilidad del negocio.
