Representación de Modelos, Datasets y Resultados

JSON como herramienta para documentar, estructurar y validar el ciclo de vida de la IA

JSON no solo sirve para mover datos, sino para definirlos. Su flexibilidad lo hace ideal para crear metadatos de modelos, definir esquemas de features y estructurar las predicciones que consumen las aplicaciones finales.

1. Metadatos de Modelo (Model Cards)

Un "Model Card" es un documento que resume el origen, la arquitectura y el rendimiento de un modelo. JSON permite automatizar este registro.

model_card.json 
{
    "modelId": "sentiment-lstm-v3",
    "framework": "tensorflow",
    "format": "SavedModel",
    "createdAt": "2025-09-12T10:30:00Z",
    "owner": "ml-platform",
    "training": {
        "datasetId": "imdb-2025-08",
        "splits": {"train": 0.8, "val": 0.1, "test": 0.1},
        "metrics": {"valAccuracy": 0.912, "testAccuracy": 0.905}
    },
    "inputs": [
        {"name": "text", "type": "string", "maxLength": 512}
    ],
    "outputs": [
        {"name": "sentiment", "type": "label", "classes": ["neg","pos"]}
    ],
    "constraints": {
        "languages": ["en"],
        "maxRPS": 200
    }
}

2. Esquema de Features y Datasets

Para evitar errores en el pipeline, definimos contratos de entrada que especifican tipos, nulidad y rangos permitidos.

schema_config.json 
{
    "schema": {
        "features": [
            {"name": "age", "type": "number", "nullable": false},
            {"name": "income", "type": "number", "nullable": true},
            {"name": "segment", "type": "string", "enum": ["Standard","Premium"], "nullable": false}
        ],
        "target": {"name": "churn", "type": "boolean"}
    },
    "quality": {
        "missingAllowed": {"income": 0.15},
        "ranges": {"age": [18, 100], "income": [0, 250000]}
    }
}

3. Petición y Respuesta de Inferencia

En producción, las aplicaciones envían instancias de datos y reciben predicciones junto con metadatos de servicio y explicabilidad.

📥 Request

{
    "requestId": "req-001",
    "modelId": "image-cnn-v2",
    "instances": [
        {"imageUrl": "https://.../img1.jpg"},
        {"imageUrl": "https://.../img2.jpg"}
    ],
    "options": {"topK": 3, "threshold": 0.25}
}

📤 Response

{
    "requestId": "req-001",
    "predictions": [
        {
            "labels": [
                {"class": "cat", "score": 0.88},
                {"class": "fox", "score": 0.07}
            ],
            "explanations": {"saliencyMapUrl": "..."}
        }
    ],
    "servedBy": "inference-pod-3",
    "latencyMs": 42
}

4. Monitorización y Resultados Agregados

Los logs de rendimiento y detección de desviación de datos (drift) se estructuran para ser consumidos por dashboards de monitorización.

monitoring.json 
{
    "window": {"from": "2025-10-05T17:00:00Z", "to": "2025-10-05T18:00:00Z"},
    "modelId": "image-cnn-v2",
    "traffic": {"requests": 15820, "errors": 12, "p95LatencyMs": 68},
    "dataDrift": {"feature": "income", "psi": 0.26, "status": "warning"},
    "accuracyRolling": 0.902
}

5. Validación de Contratos con JSON Schema

Para asegurar que los datos cumplen con lo esperado, se utilizan esquemas de validación que actúan como "puertas" de calidad.

schema_validator.json 
{
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "$id": "https://example.com/sentiment-request.schema.json",
    "type": "object",
    "required": ["text"],
    "properties": {
        "text": {"type": "string", "minLength": 1, "maxLength": 512},
        "lang": {"type": "string", "enum": ["en","es"], "default": "en"}
    },
    "additionalProperties": false
}

💡 Conclusión

La representación estructurada en JSON permite que científicos de datos, ingenieros de software y equipos de Ops hablen el mismo idioma, facilitando la auditoría, la reproducibilidad y la escalabilidad de las soluciones inteligentes.
