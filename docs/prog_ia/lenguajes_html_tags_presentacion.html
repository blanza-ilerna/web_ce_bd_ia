Etiquetas de Presentación

Evolución desde el marcado visual hacia la separación de responsabilidades

Históricamente, antes de la consolidación de HTML5 y CSS3, se utilizaban etiquetas que indicaban directamente cómo debía mostrarse el contenido (color, tipo de letra, alineación). Hoy en día, estas etiquetas se consideran obsoletas o deprecated.

¿Por qué evitar su uso?

El uso de etiquetas de presentación se considera una mala práctica moderna por varias razones estratégicas:

🌪️ Mezcla de Responsabilidades

Combinan el contenido (HTML) con el diseño (CSS), lo que hace que el código sea difícil de leer y mantener.

🏗️ Falta de Escalabilidad

Si quieres cambiar el color de todos los textos, tendrías que editar cada etiqueta individualmente en lugar de una única regla CSS.

Pasado vs. Presente

A continuación, se comparan ejemplos antiguos con la alternativa moderna recomendada utilizando CSS:

❌ Enfoque Antiguo (Obsoleto)

Etiquetas que fuerzan el estilo visual directamente en el marcado:

<font color="red">Texto en rojo</font>
<center>Texto centrado</center>

✅ Enfoque Moderno (CSS)

Uso de estilos (preferiblemente en archivos externos) para definir la apariencia:

<!-- Estilo aplicado mediante CSS -->
<p style="color: red; text-align: center;">
    Texto en rojo y centrado
</p>

💡 Regla de Oro

HTML debe utilizarse exclusivamente para definir la estructura y el significado (semántica), mientras que CSS debe encargarse de toda la capa visual. Esta separación permite que las aplicaciones de IA y Big Data procesen la información de forma mucho más eficiente y limpia.
